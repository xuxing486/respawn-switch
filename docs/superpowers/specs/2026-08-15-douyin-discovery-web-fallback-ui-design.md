# RespawnSwitch 抖音全盘检测、网页回退与界面升级设计

日期：2026-08-15  
状态：用户已批准设计方向，等待书面规格复核

## 目标

在保留现有 League 阵亡检测、倒计时悬浮窗、抖音媒体控制和复活切回能力的基础上：

1. 自动发现电脑中真实安装的 `douyin.exe`，不能只检查预设目录。
2. 找不到桌面客户端时自动打开抖音官方网页版。
3. 增加完整但紧凑的设置与扫描状态展示。
4. 将主界面重做为现代深色卡片式布局。
5. 保持故障关闭：身份不唯一时不控制未知窗口或媒体。

## 非目标与安全边界

- 不扫描网络盘或可移动设备；只扫描 Windows 报告为本地固定磁盘的卷。
- 不跟随目录重解析点、符号链接或联接点，避免循环和跨卷逃逸。
- 不绕过访问控制；无权限目录记录计数后跳过。
- 不执行扫描到的候选文件，只读取路径、版本信息和 Authenticode 签名。
- 网页回退使用系统默认浏览器打开固定地址 `https://www.douyin.com/`。
- 网页模式下不发送全局媒体键，也不尝试暂停整个浏览器；复活时只隐藏倒计时并切回 League。

## 方案概览

新增三个独立组件：

- `DouyinInstallationDetector`：协调快速来源和全盘扫描，产生进度与最终候选。
- `DouyinCandidateValidator`：验证候选文件并计算确定性的可信度排序。
- `DouyinWebFallbackLauncher`：只负责一次性打开固定官方网页。

应用启动后立即进行快速检测；快速检测失败时开始可取消的后台全盘扫描。协调器始终消费一个明确的启动计划：`Desktop`、`Web` 或 `Unavailable`，而不是自行猜测路径。

## 自动检测流程

检测按以下顺序执行：

1. 已保存且重新验证成功的路径。
2. 当前正在运行并通过身份读取的抖音进程路径。
3. Windows `App Paths`、卸载注册表和开始菜单快捷方式目标。
4. 所有本地固定磁盘的递归扫描。

全盘扫描使用显式目录队列，并具备以下行为：

- 枚举所有可用的 `DriveType.Fixed` 卷。
- 对每个可访问目录检查文件名是否精确等于 `douyin.exe`，比较忽略大小写。
- 不进入带 `ReparsePoint` 属性的目录。
- 捕获并统计 `UnauthorizedAccessException`、路径过长、目录消失和单文件 I/O 错误；单点失败不得终止整个扫描。
- 每处理固定数量的目录发布一次 `DouyinScanProgress`，包含当前卷、已检查目录数、跳过目录数、发现候选数和当前路径。
- 支持 `CancellationToken`，取消后返回 `Cancelled`，不把取消解释为“未安装”。
- 同一路径使用规范化后的 OrdinalIgnoreCase 去重。

## 候选验证与选择

候选必须满足：

- 文件存在且文件名为 `douyin.exe`。
- 能读取 PE 文件版本信息。
- `ProductName` 或文件描述能识别为抖音/Douyin，或者存在可验证的 Authenticode 签名且签名身份与已运行/已保存的可信身份一致。
- Authenticode 文件未损坏；无法读取签名的候选不会自动获得最高优先级。

确定性选择顺序：

1. 当前正在运行且身份验证通过的路径。
2. 已保存且重新验证成功的路径。
3. 注册表或快捷方式声明的已验证安装。
4. 全盘扫描得到的已验证候选，按可信度、文件版本和最后写入时间降序排列。

如果最高分仍有多个不同路径并列，则返回 `Ambiguous`，界面列出候选并要求用户选择；程序不得随机控制其中一个。用户选择后保存精确路径和签名身份。

## 网页回退

- 全盘扫描完成且没有有效候选、或用户关闭桌面客户端模式时，启动计划为 `Web`。
- 游戏阵亡时扫描仍未完成，则该死亡周期只打开一次网页版，扫描继续在后台执行；后续周期可使用新发现的桌面客户端。
- 网页通过 `ProcessStartInfo` 的 `UseShellExecute=true` 打开固定 HTTPS 地址。
- 同一复活周期设置一次性标记，避免轮询导致重复打开标签页。
- 网页打开失败时记录中文错误，倒计时悬浮窗仍继续工作。

## 设置与迁移

`AppSettings` 增加：

- `AutoDetectDouyin`，默认 `true`。
- `OpenWebFallback`，默认 `true`。
- `PreferredDouyinPath`，自动检测或用户选择后的精确路径。
- `DiscoveryMode`，值为 `Auto`、`Manual` 或 `WebOnly`。
- `LastValidatedSignatureThumbprint`。

现有 `DouyinPath` 字段在读取旧 JSON 时迁移为 `PreferredDouyinPath`；旧文件缺少新字段时应用默认值。保存继续使用同目录临时文件加原子替换。

设置界面提供：

- 自动检测开关。
- 找不到客户端时打开网页版开关。
- 当前路径只读展示与“手动选择”按钮。
- “重新扫描全部本地磁盘”和“取消扫描”按钮。
- 候选列表及“设为首选”操作。
- 当前工作模式、签名验证状态和扫描进度。

## 界面布局

主窗口改为约 820×620 的深色卡片布局：

- 顶栏：RespawnSwitch 名称、简短说明、监控状态胶囊和主开关。
- 状态区：League、抖音来源、媒体控制三个等宽卡片；图标、状态和简短说明保持对齐。
- 快捷操作区：开始/停止、测试悬浮窗、打开抖音、重新扫描。
- 设置卡片：自动检测、网页回退、路径、候选选择。
- 底部日志：默认紧凑高度，可滚动，使用等宽字体显示时间和事件。

视觉使用接近黑色的蓝灰背景、白色主文字、灰色次文字，抖音红作为主要强调色，绿色/橙色/红色仅表示成功、等待和错误。按钮、卡片和输入框使用统一圆角、边框和间距；不依赖图片资源。

## 运行时数据流

1. 主窗口加载设置并立即启动检测器。
2. 检测器发布进度，界面实时更新，但不阻塞 League 监控。
3. 阵亡事件到达时：
   - 有有效桌面计划：沿用现有窗口定位、GSMTC 播放和恢复流程。
   - 无桌面计划且网页回退启用：打开官方网页一次并显示倒计时。
   - 无可用计划：只显示倒计时和中文诊断。
4. 复活事件到达时：
   - 桌面模式：暂停已唯一验证的抖音会话、恢复窗口、切回 League。
   - 网页模式：不控制浏览器，只切回 League。
5. 后台扫描若稍后找到客户端，更新设置和界面，供下一周期使用。

## 错误处理

- 扫描错误按目录隔离，不中断其他卷。
- 磁盘被移除或目录在扫描中消失时记录并继续。
- 候选验证失败不会作为可执行路径保存。
- 网页启动失败不会影响倒计时和 League 恢复。
- 多候选不唯一时保持 `Ambiguous`，不自动控制。
- 所有扫描、网页打开和设置保存错误以中文状态和结构化日志呈现。

## 测试策略

先写失败测试，再实现：

- 已保存有效路径优先于扫描候选。
- 已保存路径失效后继续检测其他来源。
- 所有本地固定卷均进入扫描；网络盘和可移动盘被排除。
- 重解析点和无权限目录被跳过且扫描继续。
- 文件名匹配、路径规范化和候选去重。
- 有效签名/产品信息候选的确定性排序。
- 最高分并列返回 `Ambiguous`。
- 旧设置 JSON 正确迁移并保留用户路径。
- 扫描未完成时每个死亡周期只打开一次网页。
- 找到桌面客户端时绝不打开网页。
- 网页回退关闭时不打开网页。
- 取消扫描不被误判为“未安装”。
- WPF Release 构建、全套既有测试、`--self-test` 和最终 ZIP 解压自检继续通过。

## 验收条件

- 在测试提供的多卷文件系统中能发现非标准目录的抖音安装。
- 实际界面启动后不因全盘扫描失去响应。
- 界面能显示扫描进度、候选、当前来源模式和错误。
- 无客户端时，阵亡周期只打开一次官方网页。
- 客户端存在时继续使用桌面窗口与定向 GSMTC，不触发网页。
- 复活倒计时与 League 恢复行为不回退。
- 发布包为 Windows x64 自包含目录 ZIP，并通过自动化验证。
