# 操作要求

## 用户使用要求

1. Windows 10 1809 或更高版本，x64。
2. League 必须使用无边框或窗口化模式；独占全屏不属于支持范围。
3. 正常启动不要求管理员权限，也不要求预装 .NET。
4. 用户在使用前自行打开抖音桌面客户端或唯一的 Chrome/Edge 抖音网页；程序不扫描磁盘、不猜测路径、不自动启动抖音。
5. 桌面客户端只接受运行进程与唯一窗口、唯一 GSMTC 会话均可验证的目标。
6. 网页版必须安装随包扩展，只支持 Chrome 和 Microsoft Edge，Firefox 暂不支持。
7. 网页扩展只控制唯一 `douyin.com` 标签页的可见视频；目标不唯一时失败关闭。
8. 首次部署后应在训练模式验证一次阵亡、倒计时、复活、暂停和焦点恢复。

## 程序安全要求

1. 不打开 League 进程句柄，不注入代码，不模拟键鼠输入。
2. 不使用全局媒体播放/暂停键控制浏览器或其他应用。
3. 不扫描本机磁盘，不根据常见路径启动任何可执行文件。
4. 不使用空格键或全局媒体键；桌面端调用 GSMTC，网页端调用当前可见视频的 `play()` / `pause()` 并验证状态。
5. 候选窗口、媒体会话或网页标签并列时必须失败关闭。
6. 浏览器桥接只绑定 `127.0.0.1`，扩展权限只覆盖抖音域名和本机桥接地址。
7. 每个阵亡周期使用一次复活时间锚点，并用单调时钟在本地倒计时；复活仍以 Riot 存活状态确认。
8. 设置保存到用户本地应用数据目录，不保存密码、令牌或账号信息。
9. 切换到抖音时只静音当前 League 游戏进程；返回游戏、切换失败或程序退出时恢复程序实际改动过的音频会话，不改变抖音、系统总音量、其他进程或用户原本的静音状态。
10. 每个阵亡周期独占媒体、网页、窗口和音频资源；复活一旦确认，本周期不得再提交 Play，必须等待进入任务结束后按暂停、还原窗口、聚焦游戏、恢复声音的顺序清理。
11. 桌宠交互只处理自身窗口内的鼠标事件，不安装全局鼠标或键盘钩子。

## 开发与交付要求

1. 使用 .NET 8、WPF、Windows x64、自包含、多文件发布；不启用 trimming 或单文件发布。
2. `work`、`artifacts`、`outputs`、`bin`、`obj`、测试结果和 ZIP 不进入 GitHub。
3. 每次发布运行 Release 构建、完整测试、源程序自检、发布包自检和 SHA-256 核对。
4. 最终交付目录只放可直接使用的包、校验文件和快速说明。
5. 真实对局未验证的部分必须如实记录，不能用构建成功代替实际环境验证。
