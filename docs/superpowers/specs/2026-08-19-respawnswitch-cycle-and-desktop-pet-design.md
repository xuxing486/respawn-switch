# RespawnSwitch 0.3.6 切换可靠性与贴边桌宠设计

作者：**Stress Monster**  
日期：2026-08-19

## 目标

本版同时完成两项紧密相关的改造：

1. 消除阵亡/复活期间 Play、Pause、窗口置顶、窗口还原、League 焦点和游戏音频之间的竞态，确保同一个复活周期只能按确定顺序运行。
2. 将当前 930×650 普通主窗口改造成透明、可拖动、可贴边收起的 Q 版猫娘桌宠；普通用户只通过角色、状态灯和气泡理解当前状态。

现有 League Live Client 读取、英雄/KDA/复活倒计时悬浮窗、桌面抖音精确 GSMTC 会话、Chrome/Edge 网页桥接、League 进程静音与无边框窗口切换继续保留。

## 已确认根因

当前间歇故障不是固定路径或媒体身份失效。现场检查时，桌面抖音存在唯一 `electron.app.douyin` GSMTC 会话，状态可读取，Play/Pause 能力也可识别。风险来自跨组件的生命周期管理：

- `RespawnCoordinator.media` 是所有周期共享的字段，而不是某个 `RespawnCycleId` 的资源。
- 桌面周期在媒体控制器写入共享字段之前就被标记为已连接；复活恰好发生在该间隙时，返回流程可能没有正确控制器可暂停。
- `RespawnCycleRunner.CancelAsync` 超时后将任务移出表，但没有阻止原任务以后继续保存状态、播放或置顶抖音。
- GSMTC 命令成功返回后立即读取一次状态，无法容忍抖音异步更新播放状态的短暂延迟。
- 返回流程忽略 Pause、窗口还原和焦点恢复的结果，因此“切回游戏”不代表“抖音已暂停”。
- 返回流程以 fire-and-forget 启动，缺少每周期的单写者和终态约束。
- 网页 Play 在复活后迟到完成时，也可能错过 `webCycles` 检查而未收到对应 Pause。

## 方案选择

采用方案 A：**周期状态机＋贴边桌宠**。

未采用始终完整显示的自由桌宠，因为它更容易遮挡游戏；未采用角色旁固定大状态卡，因为它会重新变成用户已经明确拒绝的面板式界面。

## 周期级协调模型

### 状态

每个 `RespawnCycleId` 拥有独立、单写者控制的状态：

```text
Created
  → EnteringDouyin
  → WatchingDouyin
  → ReturningToLeague
  → Completed
```

任何状态都可以因失败或复活直接进入 `ReturningToLeague`，但 `Completed` 是不可逆终态。进入 `ReturningToLeague` 后，迟到的 Play、Attach、保存设置或状态回调不得再修改窗口或媒体。

### 周期上下文

新增 App 层周期会话，按 `RespawnCycleId` 保存：

- 捕获的 `GameWindowTarget`；
- 桌面或网页抖音目标模式；
- 本周期专属媒体控制器或浏览器命令目标；
- 抖音窗口是否已经附着及其还原句柄；
- League 进程音频静音租约；
- 进入任务、周期取消源和终态标志；
- 本周期最后一次可公开给 UI 的简单状态或错误归属。

不再使用共享 `media`、`desktopCycles` 和 `webCycles` 判断应控制哪个周期。

### 串行与取消

- 每个周期只有一个串行执行入口；Play 与 Return 不并行写状态。
- `RespawnConfirmed` 直接触发并等待本周期的 Return；不再放任后台返回流程重叠运行。
- Return 首先设置不可逆的返回意图，再取消 Entering 操作。
- 外部操作必须各自具有明确上限，所以协调器可以等待进入任务真实结束，而不是在 750ms 后丢弃仍在运行的任务。
- 进入操作的每个外部调用完成后必须重新检查周期是否已经要求返回；检查失败时只能清理，不能继续 Play、置顶或保存设置。
- 重复的复活事件、重复 Return 和程序退出都必须幂等。

## 桌面抖音媒体控制

### Play

1. 在执行窗口附着前创建并保存本周期媒体目标。
2. Play 和窗口附着可以并行，但结果只提交给仍处于 `EnteringDouyin` 的同一周期。
3. Play 被接受后，在短时间内轮询精确会话状态，确认 `Playing`。
4. 若周期已要求返回，即使 Play 最终成功，也必须立即进入 Pause 补偿路径。

### Pause

1. Return 对本周期精确媒体目标调用显式 Pause，不发送空格键、切换键或全局媒体键。
2. 命令被接受后，以条件轮询等待真实 `Paused`；不以一次立即读取作为最终结论。
3. 第一次没有确认时，重新枚举并验证相同 AUMID 和诊断指纹仍然唯一，再显式 Pause 一次。
4. 整个确认和重试有严格的亚秒级上限，不能长期推迟返回游戏。
5. 最终仍未确认时记录“抖音没有暂停”，然后继续还原窗口和 League；游戏返回优先于无限等待抖音。

建议时间预算：首次确认约 350ms，重新解析和第二次确认约 450ms，总预算不超过 900ms。实际实现使用可测试的轮询策略，不写死不可替换的 `Task.Delay` 链。

## 网页抖音控制

- 浏览器命令携带 `RespawnCycleId` 和单调序号；只接受当前周期、当前命令的确认。
- Return 即使发生在 Play 尚未确认时，也必须发布该周期的 Pause，不能依赖“已经写入 webCycles”这一中间标志。
- 新 Pause 会使同周期的旧 Play 结果失效；迟到 Play 确认不能重新把周期变成 Watching。
- 扩展继续只控制唯一 `douyin.com` 标签页中的可见视频，并返回真实 `playing`/`paused` 状态。

## 确定的返回顺序

收到复活确认后立即隐藏已经归零的倒计时悬浮窗，随后统一执行：

1. 将周期标记为 `ReturningToLeague`；
2. 取消并收敛尚未结束的进入操作；
3. 对本周期抖音目标执行带确认的 Pause；
4. 还原本周期保存的抖音窗口状态；
5. 恢复捕获的 League 窗口前台；
6. 释放本周期 League 音频租约，恢复程序实际静音过的会话；
7. 将周期设为 `Completed` 并释放周期资源。

单个步骤失败不能阻止后续清理。返回结果要分别保留 Pause、抖音窗口、League 焦点和 League 音频的结果，UI 只显示用户能执行的故障归属。

## 桌宠窗口

### 视觉方向

- 新建一套原创透明背景 Q 版猫娘资源，保留 Stress Monster 的深蓝、薄荷绿和粉色品牌配色。
- 角色是视觉主体，不使用角色旁永久展开的大面板。
- 待机包含轻微呼吸/漂浮、随机眨眼和状态变化反馈，不增加持续高负载动画。
- 角色素材与动作层独立，后续可以替换贴图，不把状态逻辑写死在 PNG 中。

### 窗口行为

- 主窗口为透明、无边框、任务栏隐藏、可拖动的 WPF 窗口。
- 默认不强制覆盖游戏；提供“固定在最上方”开关。
- 拖到屏幕边缘后吸附并收起为探头形态；保存边缘和偏移位置。
- 鼠标悬停约 250ms 或单击角色时展开完整桌宠与气泡；鼠标离开后延时收起。
- 提供右键或托盘菜单：显示/隐藏、固定最上方、暂停/继续助手、重新检查、退出。
- 不监听全局键盘和鼠标输入；仅借鉴旧桌宠的透明分层、拖动、贴边、眨眼和气泡交互。

### 用户可见信息

常驻状态只使用四种简单表达：

- `准备中`；
- `可以开局`；
- `正在对局`；
- `需要处理`。

展开气泡只显示：

- 英雄联盟：已打开 / 请先打开；
- 抖音：已准备 / 请先打开视频；
- 当前一句话状态；
- 抖音来源选择；
- 重新检查；
- 预览悬浮窗；
- 暂停或继续助手。

GSMTC、Automation、窗口类、AUMID、异常类型和原始失败码继续隐藏，只进入开发者日志。

### 游戏期间

- League 对局存活时，桌宠保持收起或处于非置顶桌面层，不遮挡无边框游戏。
- 阵亡时仍由现有独立悬浮窗显示英雄、KDA 和本地连续倒计时。
- 桌宠不是复活倒计时的替代品，不改变已经实测有效的悬浮窗 Topmost 策略。

## 错误呈现

错误分为用户可理解的四类：

- 游戏未连接；
- 抖音未准备；
- 抖音没有暂停；
- 窗口没有切换成功。

气泡给出一条对应操作，不展示技术名词。开发者日志保存周期 ID、阶段、目标模式、命令是否接受、状态是否确认、窗口后置条件和恢复结果，用于以后定位现场问题。

## 测试策略

### 自动化回归

必须先建立失败测试，再实施修复：

- Play 尚未完成时发生复活，迟到 Play 不得覆盖 Return；
- 抖音接受 Pause、状态延迟两次读取后才变为 Paused；
- 第一次 Pause 未确认，重新定位同一唯一会话后第二次成功；
- Pause 最终失败时仍还原窗口、恢复 League 焦点和音频；
- 两个周期连续发生时不会共享媒体控制器或窗口状态；
- 重复复活和程序退出不会重复恢复或留下任务；
- 网页 Play 被 Pause 取代时，迟到确认无效；
- 旧周期回调不能改变新周期 UI 状态；
- 贴边几何覆盖左、右、上、下、多显示器工作区与缩放；
- 桌宠 XAML 契约验证透明、无边框、任务栏隐藏、简洁用语和隐藏技术面板；
- 现有悬浮窗、League 数据、媒体身份、窗口后置条件和音频租约测试全部继续通过。

### 本机媒体复测

在唯一抖音会话存在时执行安全的 Play→Pause→状态确认测试：测试前记录原状态，测试结束在 `finally` 中恢复原状态，只控制已验证的唯一抖音会话。记录命令耗时和每次状态读取，不把进程存在冒充媒体控制成功。

### 视觉与交互复测

- 渲染桌宠的展开、收起、准备、故障四种截图并人工查看透明边缘、气泡遮挡和文字可读性；
- 运行贴边动画循环和窗口生命周期测试；
- 启动最终发布版，确认任务栏隐藏、拖动、悬停展开、托盘退出和设置持久化；
- 真实 League 当前版本的完整阵亡/复活仍需训练模式验收，自动化测试不得冒充真实对局。
