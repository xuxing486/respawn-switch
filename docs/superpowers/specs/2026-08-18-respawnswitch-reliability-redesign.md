# RespawnSwitch 可靠性重构设计

日期：2026-08-18  
状态：用户已批准，可直接实施

## 目标

修复实际使用中的卡顿、阵亡后不显示抖音、不自动播放、复活后不暂停或不返回游戏、悬浮倒计时不递减，以及主界面无法判断各组件是否真正就绪的问题。

产品继续只读取本机玩家可见的游戏状态，不读游戏内存、不注入、不模拟游戏输入。抖音桌面客户端和 Chrome／Microsoft Edge 抖音网页版均受支持；Firefox 暂不支持。

## 使用前提

- League 使用无边框或窗口化模式。
- 用户在正式游戏前自行打开并登录 League 客户端。
- 用户自行打开抖音桌面客户端并进入视频页面，或安装随产品提供的 Chromium 扩展并打开抖音网页视频。
- RespawnSwitch 不再扫描硬盘寻找抖音，也不自动启动未知路径的客户端。

## 两阶段就绪模型

### 赛前准备

检测可见的 League 客户端窗口、后台监控、悬浮层、返回热键，以及所选抖音目标。全部通过时显示“赛前准备完成 · 等待进入对局”。该状态不冒充对局数据连接，也不读取 League 登录令牌或不受支持的私有 LCU 接口。

### 对局运行

检测到 `League of Legends.exe` 无边框窗口和本机 `127.0.0.1:2999` Live Client Data API 后，读取本机 Riot ID，并在 `playerlist` 中精确匹配本人。成功后显示“对局数据已连接 · 阵亡检测正在运行”。

## 游戏采样与本地倒计时

- 进入对局时只读取一次本机玩家身份；不再每 250 毫秒重复读取 `activeplayer` 和 `gamestats`。
- 存活期间轮询必要的 `playerlist` 以检测 `isDead`。
- 首次确认阵亡时，从同一份样本只采用一次有效 `respawnTimer`，使用单调时钟建立本周期截止锚点。
- WPF 悬浮层使用独立计时器每 100 毫秒刷新，整数按向上取整显示，不依赖抖音窗口或媒体操作。
- 阵亡期间仅低频确认 `isDead`；预计复活前一秒提高确认频率。后续样本不重新锚定倒计时。
- 本地计时归零但 `isDead` 仍为真时显示“正在确认复活”；接口失联时显示“连接不稳定”，不得把失败当成复活。
- 确认 `isDead=false` 后立即取消未完成的媒体任务、暂停目标、隐藏悬浮层并恢复游戏。

## 悬浮层内容

悬浮层保持透明、无边框、置顶、不抢焦点和鼠标穿透，显示：

- 当前英雄名；
- 当前 KDA，格式为 `击杀 / 死亡 / 助攻`；
- 本地复活倒计时；
- 必要时显示连接或媒体故障短状态。

英雄与 KDA 来自首次阵亡样本；阵亡周期内不为视觉更新额外高频读取接口。新周期使用新的样本更新。

## 抖音目标

### 桌面客户端

要求用户预先打开。程序查找唯一可见抖音主窗口和唯一 `electron.app.douyin` GSMTC 会话。阵亡发送明确 `Play`，复活发送明确 `Pause`，每次重新读取状态验证。不得使用空格、全局媒体键或坐标点击。

窗口以非激活置顶覆盖方式显示在 League 上方，保存并按本周期恢复原位置、大小、可见性和置顶状态。操作后必须验证 HWND、可见性、矩形和 Z 序。

### Chrome／Microsoft Edge 网页版

提供 Manifest V3 扩展。扩展权限限制到实际需要的抖音域名，不读取 Cookie、密码、浏览历史或其他网站。扩展通过仅绑定 `127.0.0.1` 的本机 HTTP 桥接与桌面程序通信，精确识别唯一抖音标签页，对当前可见视频执行幂等 `play()`／`pause()` 并验证 `paused` 状态；需要时激活对应标签页和浏览器窗口。

多标签页或多个目标时停止自动动作并要求用户在赛前选择。每个阵亡周期锁定一个目标，不在周期中途切换媒体源。

### 目标选择

设置支持“自动选择、桌面客户端、抖音网页版”。自动模式只有一个目标就绪时直接使用；两者均就绪时使用用户上次明确选择的首选目标；两者均未就绪时显示具体阻塞项。

## 非阻塞周期编排

League 采样与状态机永远不等待窗口、浏览器或媒体操作。每次阵亡创建一个带取消令牌的周期任务：悬浮层立即启动，抖音显示和播放在后台运行。复活事件优先取消未完成的附着任务并开始清理，避免短复活周期被 1 至 10 秒的外部等待吞掉。

## 前端

主界面采用简洁深色布局：顶部总状态、三张连接卡片、一个主要操作区和可折叠诊断区。

- League 卡片：客户端、对局数据、游戏窗口、存活状态。
- 抖音卡片：当前目标、窗口或标签页、Play/Pause 能力。
- 自动流程卡片：悬浮层、返回热键、当前周期。

总状态限定为“等待 League 客户端、正在赛前检查、赛前准备完成、对局监控中、部分功能未就绪、需要处理、已停止”。绿色只表示对应前置条件已真实验证。

错误使用结构化组件和代码，不再通过中文字符串猜测颜色。组件包括 `LeagueClient`、`LeagueGameData`、`LeagueWindow`、`DouyinDesktop`、`DouyinWeb`、`MediaControl`、`WindowsFocus`、`Overlay`。每个问题显示所属组件、原因、建议操作和最近检测时间。

## 诊断与恢复

记录脱敏滚动日志：状态转换、窗口结果、媒体结果、倒计时锚点、取消原因和耗时。不得保存 Riot 登录信息、抖音 Cookie、密码或完整 API 响应。界面提供“重新检测、测试悬浮层、测试 Play/Pause、打开日志目录”。媒体测试必须恢复测试前状态。

Windows 拒绝焦点恢复时不得循环抢焦点或模拟 Alt；显示明确提示并保留返回热键。

## 验收

- 赛前无需进入对局即可验证 League 客户端、抖音目标、媒体、悬浮层和热键。
- 进入对局后自动连接 Live Client，无需用户返回设置页。
- 抖音外部操作阻塞 10 秒时，游戏状态循环和本地倒计时仍继续。
- 预览与真实悬浮层连续倒计时，显示英雄和 KDA。
- 复活事件可取消未完成附着，并在确认后执行 Pause、恢复窗口和隐藏悬浮层。
- 桌面 GSMTC 与 Chrome／Edge 扩展分别通过 Play/Pause 状态验证。
- 每个失败均归属到 League、抖音桌面、抖音网页、媒体、Windows 或悬浮层。
- Release 构建零错误，完整自动测试、自检、打包程序启动关闭测试通过。
- 最终成品复制到桌面长期 Codex 工作区的独立交付目录，源项目和历史记录同步更新。
