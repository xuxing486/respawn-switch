# 用户需求与操作历史

本文件保存经过整理的项目需求与实现决策，不包含账号凭据、令牌、验证码或私人数据。

## 2026-08-10 至 2026-08-15

1. 初始目标：程序读取 League 游戏状态；英雄阵亡时自动打开电脑上的抖音并显示复活剩余时间；英雄复活后自动暂停抖音并切回游戏。
2. 窗口要求：League 使用无边框或窗口化模式；倒计时采用透明、无边框、置顶、鼠标穿透且不抢焦点的悬浮窗。
3. 实施方式：用户授权按推荐方案直接制作成品，减少重复确认，以实际可运行包作为完成条件。
4. 抖音发现升级：不能只检查常见安装位置，必须扫描电脑确认真实位置。
5. 发现范围：快速检查已保存路径、运行进程、注册表和开始菜单；找不到后扫描全部本机固定磁盘。
6. 安全要求：不执行未验证候选；跳过网络盘、移动盘、联接点和无权访问目录；候选不唯一时不自动运行。
7. 网页回退：找不到可信桌面客户端时打开固定官网 `https://www.douyin.com/`；每个阵亡周期最多一次。
8. 复活行为：桌面抖音模式尝试暂停并恢复窗口；网页版模式不发送全局媒体暂停，只恢复 League。
9. 设置与界面：增加自动/手动/仅网页版模式、网页回退开关、全盘扫描、取消、候选列表、手动选择和现代化深色卡片界面。
10. 交付要求：生成自包含 Windows x64 ZIP、校验文件和中文快速说明；运行完整构建、测试、自检、启动关闭与最终 ZIP 复测。
11. 归档与发布：将项目、历史、操作要求、旧文件和最终成品放入桌面 Codex 长期工作区，并发布经过清理的源码到 GitHub。

## 关键版本

- 0.1.0：基础阵亡/复活协调、悬浮倒计时、桌面抖音窗口和媒体控制。
- 0.2.0：完整固定磁盘发现、候选验证、网页回退、后台扫描、设置迁移和新版界面。
- 0.3.0：按真实使用反馈移除全盘扫描与自动启动；用户提前打开抖音。桌面端使用定向 GSMTC，Chrome/Edge 网页使用随包扩展的明确 Play/Pause；阵亡周期只读取一次计时锚点并本地连续倒计时，悬浮层增加英雄和 K/D/A；赛前显示 League、抖音和自动流程的独立连接诊断。
